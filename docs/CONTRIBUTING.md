# Contributing

Thank you for helping improve DevImpact documentation and public resources.

## Before making a change

- Read the relevant documentation, especially [Governance](GOVERNANCE.md) and [Principles](PRINCIPLES.md).
- Confirm that the change belongs in this repository.
- Keep the change within the approved five-repository structure.
- Do not include private information or credentials.

## Documentation standards

- Write in clear, direct English.
- Use descriptive Markdown headings.
- Prefer relative links for documents in this repository.
- Use meaningful link text rather than phrases such as "click here".
- Verify links and factual statements before publishing.
- Mark proposals as proposals; do not present them as completed work.
- Keep documents focused and avoid unnecessary duplication.

## Repository workflow

The approved default branch is `main`.

For owner-authorized changes, keep the work focused and inspect the resulting diff before committing. A discrete task should normally be delivered as one coherent commit. Do not create additional branches or pull requests, or trigger workflows, unless specifically authorized.

## Scope restrictions

A documentation contribution must not independently:

- Create or delete repositories.
- Change repository visibility or organization membership.
- Enable GitHub Pages, Actions, or other automation.
- Add external integrations, paid services, or infrastructure.
- Publish material from private repositories.

Those changes require separate explicit approval from the organization owner.

## Reporting an issue

For a correction or documentation problem, use the repository's GitHub issue or discussion facilities if they are enabled. Otherwise, contact the organization owner through the official GitHub organization.
