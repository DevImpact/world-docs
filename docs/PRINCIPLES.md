# DevImpact Principles

These principles guide the way DevImpact repositories and public resources are maintained.

## 1. Clarity

Every repository should have a clear purpose, a useful description, and documentation that explains how its contents should be used.

## 2. Deliberate growth

Keep the ecosystem small and understandable. Do not add repositories, services, integrations, or infrastructure simply because they are available.

## 3. Transparency

Describe the current state honestly. Separate completed work from proposals, experiments, and future plans.

## 4. Security and privacy

Never commit passwords, access tokens, private keys, personal records, or other secrets. Keep private information in its approved private location and share only what is necessary.

## 5. Maintainability

Prefer simple, readable solutions over unnecessary dependencies or complexity. Keep documentation close to the work it describes and update it when the work changes.

## 6. Accessibility

Use descriptive headings, meaningful link text, readable contrast, and straightforward language. Public information should be understandable on desktop and mobile devices.

## 7. Responsible automation

Automation must have a clear purpose, limited permissions, and owner approval. No workflow should be enabled or manually triggered merely for convenience.

## 8. Respect for users and communities

Build and publish products responsibly. Respect platform rules, intellectual property, user privacy, and applicable laws.

## 9. Consistency

Use the approved repository responsibilities and naming conventions. Avoid duplicating authoritative information across multiple locations.

## 10. Continuous improvement

Improve the ecosystem incrementally. Prefer small, verifiable changes that preserve existing work and are easy to maintain.
